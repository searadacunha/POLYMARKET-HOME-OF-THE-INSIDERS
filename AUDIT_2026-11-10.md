## 1. Findings that required correction

### KPMG: distinguish populations, success rules and announcement cutoffs

The current findings index previously described a 22-account network while
quoting the original 19-account subgroup's statistical results. The archived
tables give these different records:

| Population | Markets | Aggregate main side wins | Every account's main side wins |
|---|---:|---:|---:|
| Original 19 accounts | 21 | 20 | 18 |
| Expanded 22 accounts | 21 | 20 | 17 |

The original generator also reused the aggregate main-side probability for
the event that every account's main side wins. When accounts hold opposite
main sides in the same binary market, that latter event is impossible.
Reproducing a Poisson-binomial calculation with the wrong event probabilities
does not validate its statistical interpretation.

The overview now reports the descriptive counts without presenting those
tails as calibrated evidence. It specifies that 19 cutoffs are SEC acceptance
timestamps and two are market-close fallbacks. A filing timestamp is not
automatically the first public earnings announcement. The original tables
and generator remain intact, with a [dated correction and offline replay](research_notes/kpmg-statistical-correction-2026-11-10/REPORT.md).

### G38: preserve transaction facts and state the limits of the new RPC records

The four added Polygon log exports reconcile 53 incoming and 30 outgoing
records, including zero-value records, to **1,984,038.168550 USDC/USDC.e in
each direction**. This is gross observed flow, not the sum of incoming and
outgoing amounts and not trading profit.

The reconciliation now rejects repeated receipt identities, repeated Relay
order IDs, inconsistent blocks, and fractional or Boolean quantities that
Python's `int()` could otherwise accept or truncate. It compares the 38
direct receipts and 12 Polygon Relay credits with the earlier Etherscan and
Relay archives, rather than trusting a count of summary rows.

The added JSON files containing `block_match` and `order_id_in_live_input`
are derived summaries. They do not contain every raw transaction input and
receipt required to independently reproduce the reported seven on-chain
order-ID matches or the two Base receipts. The verifier explicitly reports
those operations as outside its replay scope. Likewise, request counters
and 86 failed-split attempts do not prove complete block-range coverage.
The result remains `NOT_ESTABLISHED` for historical exhaustiveness.

These distinctions are recorded in the [current findings index](VERIFIED_FINANCIAL_FINDINGS.md#1-iran-cohort-38-proxies-and-separately-verified-payout-routes),
the [RPC audit with its scope clarification](research_notes/independent-forensic-audit-2026-11-08/REPORT.md)
and the [offline reconciliation](scripts/check_polygon_rpc_coverage.py).
No exchange customer account, beneficial owner or information source is
identified by these fixes.

### Ballon d'Or: distinguish archived long-form text from the rechecked short post

The October 16 syndication response explicitly contains the five-name
ranking. The rechecked October 14 response confirms its timestamp and a
discussion of a large position, but does not contain that full ranking.
The index now distinguishes this primary short response from the separately

The [two archived responses](research_notes/independent-forensic-audit-2026-11-08/evidence/ballon_syndication_2026-11-08.json)
and earlier reconstruction are both retained.

## 2. Demonstrated implementation defects

| Area | Previously reproducible failure | Corrected behavior |
|---|---|---|
| Token-unit conversion | Default Decimal precision rejected an exact 29-digit amount and accepted a rounded alternative | Exact exponent-based normalization preserves every raw digit |
| Financial graph | A zero-value ERC-20 event created a payment or common-funder link | Keep the event in canonical evidence, exclude it from value-transfer links; positive dust remains visible |
| Temporal null model | Mixed-case spellings of one wallet counted as different traders in permutations | Use the same normalized wallet identity for observed and randomized pairs |
| Numerical citation check | `21000.50` supported a claim of `1000.50`; a negative value could support a positive claim | Compare complete signed numeric values, including grouped formats and explicit magnitudes |
| Gzip import and public scanning | Header text in later concatenated members escaped scanning; uppercase suffixes and invalid deflate had inconsistent treatment | Scan all member bodies and metadata with bounded input/output, checksum validation and fail-closed errors |
| Polygon matching | Duplicating a receipt or order preserved the expected list length and passed | Verify unique event/order identities and membership against the earlier archives |
| Polygon quantities | Fractional atomic amounts were silently truncated | Require exact nonnegative integers or valid integer strings, including hexadecimal quantities |
| Etherscan pagination | Lexicographic order put page 10 before page 2 | Sort numbered pages numerically and still reject gaps |
| Citation and restoration paths | Parent paths could read self-cited claims or restore outside the selected destination | Reject escaping paths and resolved symlink escapes |
| Publication policy | A candidate could change its own policy; a local uncommitted policy could then be trusted despite unchanged committed policy blobs | Compare with the destination and load the reviewed policy from Git objects |
| Historical replay | Missing local raw data replaced an earlier archived verification result with a skipped run | Default replay is read-only, writes calculations to temporary output, and reports skips separately |

The corrections live in the [forensic integration](integrations/forensic-intelligence/ledger.py),
[temporal routines](integrations/forensic-intelligence/temporal.py),
[evidence validator](scripts/validate_evidence.py),
[gzip scanner](scripts/phi_lib.py),
[publication guard](scripts/check_publication.py) and
[historical verifier](research_notes/x-history-2026-11-06/verification/verify.py).
Synthetic regression cases exercise the failures without real credentials,
network writes or changes to source evidence.

The historical X verifier now reports **20 executed checks** and **one
skipped raw-archive component** in a clean public checkout. To retain a
current run separately, use `--output` with a new, non-existing JSON path.
It refuses to overwrite an existing result. Availability of the unpublished
raw tapes is still required for the skipped component.

Publication verification checks committed Git objects against the current
destination. A successful local or GitHub run establishes the tested
properties; it does not by itself establish server-side branch protection.
