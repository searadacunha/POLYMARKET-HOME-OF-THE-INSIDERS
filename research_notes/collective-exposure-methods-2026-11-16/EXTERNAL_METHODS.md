# Technical review of related public work

**Review date: 2026-11-16.** These are observations from the named repositories' published documentation or code. Their reported figures are **author-reported** unless separately reproduced here, which they have **not** been. No code or data from these repositories is vendored in this research note.

| Upstream project | What it demonstrably implements or documents | Source-reported outcome and verification limit | Practical adaptation to our investigation |
|---|---|---|---|
| [intelliFi Anomaly Detection](https://github.com/SoweluAvanzo/intelliFi_anomaly_detection) | `PROJECT_OVERVIEW.md` and `REPRODUCING.md`: co-trading in 300-second bins; lead/lag within 600 seconds; activity-preserving nulls, multiple-testing correction; one-to-one BUY-to-SELL matching on the **same asset** with >=50% overlap within 600 seconds; leader-copy placebo at delayed price | Initial sample: 100 volume-selected markets, 382,554 taker-side API trades, 92/100 capped. Authors report 19 fast-flip wallets and no robust coordination/copy edge. Their later *reported* full-tape replication also gives null signals. Dataset selection and incomplete feed are major limitations | Adopt the **activity-preserving null, placebo matching, multiple-testing correction and negative examples**. Do NOT mistake BUY→SELL on one token for NO→YES across different deadline markets. Require complete fill tape before claiming skill |
| [Polymarket Intel](https://github.com/TheophilusChinomona/polymarket-intel) | `analysis/correlation.py` groups observed BUY actions by (market slug, outcome) and scores multi-wallet consensus from prior wallet scores and volume | Repository describes a detector and paper-trading architecture; the reviewed module alone does not show out-of-sample edge. Recent-trade query is capped and can miss activity | Use BUY consensus as a **simple baseline** to beat; do not import raw scores or call it validated alpha. Replace gross BUY agreement with reconstructed net payoff changes |
| [Polymarket Smart Money](https://github.com/darrnhard/polymarket-smart-money) | `notebooks/01_fetch.ipynb` is described as checkpointed adaptive historical pagination, and `02_analysis.ipynb` as lead/follow timing | Authors report ~6.8M account events for **three preselected high-performing** wallets and lead/follow metrics. Bulk parquet is excluded from Git and copy-trade profitability is deferred | Independently implement resumable time-window paging as needed and leader/follower features **with an unselected comparator**. Do not infer coordination merely from overlap or timing |
| [ScrapingBee Polymarket API](https://github.com/ScrapingBee/polymarket-api) | `README.md` describes discovery of deadline ladders and a monotonicity check for comparable "by date" contracts | Snapshots are site-dependent and not evidence of historic execution. Events with different resolution terms are not automatically nested | **High-priority semantic control**: normalize deadlines and exact market rules before calling NO on D1 followed by YES on D2 a reversal |
| [wietrade/poly_data](https://github.com/wietrade/poly_data) | `README.md` and pipeline index V2 standard CTF exchange order fills, enrich by CLOB metadata, write parquet | Its own scope declaration says **standard CTF V2 only**, not NegRisk V2 or V3. It is not a complete universe for event-wide prevalence | Use its ETL shape as a reference for quality and checkpointing, but never adopt its counts as a complete market tape |
| [bandrehc/polywash](https://github.com/bandrehc/polywash) | Documents pairing Data API fills for possible wash-like counterparties and refers to network-based scoring | The author's pairing approach is heuristic on API aggregates and is not proof of canonical execution matching under complex order modes | Prefer first-party on-chain order/receipt identities. Never use inferred counterparty adjacency as beneficial-ownership proof |
| [OpenMarket](https://github.com/gregyoung14/openmarket) | Large synchronized Polymarket/Binance BTC research corpus; docs emphasize source-versus-ingest clocks, walk-forward protocol and benchmark pricing | Authors report an out-of-sample **null economic result despite model signal**. BTC high-frequency microstructure is not a geopolitical-events population | Import the *principle* of recording when information becomes observable and evaluating executable post-alert prices, not any BTC model or PnL |
| [PerlanLabs paper trader](https://github.com/PerlanLabs/polymarket-paper-trader) | Software for simulated positions, orders and PnL using market feeds | Simulated fills and displayed ROI depend on feed completeness and execution assumptions; an application is not a controlled field trial | Use paper-trade semantics only when the order-book snapshot, fee regime, depth and fill assumptions are stored |

## What these other works establish or fail to establish

1. **Not novel**: rapid flips, wallet co-trading, and follower consensus are already studied. A simple "several wallets buy YES" detector is a baseline, not an original discovery.
2. **Negative evidence matters**: intelliFi's reported full-tape placebo study and OpenMarket's reported economic null reduce our justification for assuming any raw wallet pattern yields alpha.
3. **The remaining empirical gap** is narrowly defined: a true **net payoff-vector rotation** across comparable event deadlines, detected only with knowledge available at the time, evaluated against group-activity nulls and the then-executable market price.
4. **Source-specific risk**: timestamps from public activity feeds may be truncated, maker/taker roles can be incomplete, positions cannot be inferred from buys alone, and NegRisk conversions change apparent token inventory.
5. **No population-wide discovery is claimed here**. External reported outcome counts are not imported into our local CONFIRMED findings; new claims must be reproduced on a defined, unselected dataset.
