# Repository reliability audit, 4 November 2026

Code and investigation snapshot reviewed: `f25580ce7ff1d60a5dc1dbb16dc768ff00b3c736`.
Publication also preserves the automatic backup/report update at
`2da3eae1c923a6a1c7f8f277f85ccb09717fdd1b`; that intervening commit changes
backup metadata and generated reports, not the reviewed code or source evidence.

This audit corrects reproducible implementation defects and the overview of
existing findings. It does not establish insider trading, validate all research
conclusions, or inspect the running Mac sessions and external disk.

## Confirmed implementation defects

| Area | Failure reproduced | Correction |
|---|---|---|
| Abbreviated addresses | Only the prefix was checked, allowing an incorrect suffix. | Require the prefix and suffix together in the cited source. |
| Finding references | Missing investigations or finding files were silently ignored. | Report invalid cross-references. |
| Finding syntax | Malformed headings could disappear from the parsed findings. | Reject malformed finding headings explicitly. |
| Evidence sources | A directory could satisfy a reference intended to name an evidence file. | Require files; navigation directories are documented separately. |
| Hash tables | Malformed hash rows could be skipped by the regular expression. | Validate rows within explicitly headed SHA-256 tables, while allowing unrelated service tables. |
| Evidence refresh | `--fill` could update recorded hashes despite validation failures. | Preserve evidence tables when validation fails. A valid re-import can still refresh hashes. |
| Compressed input | The gzip scanner treated a bounded partial read as a complete scan. | Refuse decompressed content beyond the configured limit. |
| Import races | A source could change after scanning and publish unchecked bytes. | Recheck the exact copied bytes and their size before accepting them. |
| Archive membership | Duplicate TAR names could hide a missing member in the count. | Track unique expected members and reject duplicates or non-files. |
| Restore completeness | A missing requested TAR member could leave a successful return status. | Count and report missing members. |
| Restore integrity | Corrupt input could overwrite an existing good file before its hash failed. | Stage the content and replace the destination only after its hash matches. |
| Disk export retry | An export failure still advanced the exported commit, preventing a retry. | Advance the commit only when all exports succeed. |
| Git export integrity | Failed blob reads or incorrect bytes could be recorded as successful exports. | Check the Git result, blob hash and written-file hash before recording success. |

These fixes are limited to central scripts. No file in an imported `sources/`
tree, original investigation manifest, frozen protocol or archived result is
changed. Recovery regressions operate on synthetic temporary files and archives.

## Documentation and accounting corrections

The English README now distinguishes the eleven-account Ballon d'Or cash-flow
scope, the seven settled-account subset and the separate eight-account
Maduro/Iran study. It links each result to its evidence and distinguishes
repository validation from scientific or operational validation.

read the committed per-account JSON, not new RPC responses. Cash flow is not a

For the eight-account Maduro/Iran cohort, the archived JSON sums to
$509,993.244904 before cent rounding, or **$509,993.24**. Adding the already-rounded
CSV PnL rows instead produced the historical $509,993.25 headline. The one-cent

[`accounting_audit_2026-11-04.json`](investigations/maduro-iran/results/accounting_audit_2026-11-04.json),
with selected addresses, formula, source hashes and limits. Original source

equal $509,624.54, a separate measure.

The overview also separates files absent from a clone from separately encrypted
backups. `BACKUP_STATUS.md` is a dated status record, not proof of present
collector health or a new restore test. The automatic backup update during this
audit is preserved, not attributed to these corrections.

Two authored documents described Relay v2 retirement imprecisely. The
[official API documentation](https://docs.relay.link/references/api/get-requests-v2),
checked on 4 November 2026, says the endpoint is deprecated and scheduled for
retirement on 24 November 2026; its v3 successor requires authentication. The
authored wording is corrected. Original captured sources remain unchanged.

The initial regression run exposed 15 failed assertions in 14 methods on the
previous code. Subsequent cases also cover unrelated tables in evidence documents
and failed/incorrect Git blob reads. The complete corrected suite passes.

PolySentinel ran in an isolated copy of its source snapshot, with `httpx 0.28.1`
and `networkx 3.4.2`; its environment-specific SOCKS dependency was added to
resolve two client-construction errors. This is not a complete reproduction of
every historical dependency lock. A global undefined-name scan also found three
`X()` warnings in historical phase-9 scripts; `X` is defined by the fragment
those scripts load dynamically, so no speculative edit was made to the archives.

The new `Repository integrity` GitHub workflow uses a complete checkout and runs
the central self-checks, the regression suite, full evidence validation and
generated-report freshness. It uses read-only repository permission and does not
run collectors, decrypt backups or access service credentials. Its actual outcome
is recorded in the pull request's checks, separately from the local results above.

## Limits that remain

- Some large private binary files cannot be retrieved through the available
  connector. The local working copy is therefore partial; the full local
  `validate_evidence.py` gate cannot be claimed from this copy. The CI workflow
  is provided to execute that gate on a complete GitHub checkout.
- The complete backup E2E test requires macOS utilities and a SQLite CLI with
  `sqlite_dbpage`. The official age binary was obtained and its published hash
  verified, but the full backup test remains unvalidated in this Linux session.
  The targeted TAR, restore and export regressions did run successfully.
- Raw historical captures, the external drive, live sessions and sealed replay
  inputs were unavailable. No new chain collection or frozen-study rerun was
  launched. Syntax and unit tests do not certify every execution path.
- Existing research PRs #11 and #12, and backup PR #3, are not merged by this
  change. Their own review conditions and unresolved issues remain relevant.

The scientific distinctions remain unchanged: financial transfers are not proof
of common control, a shared service is not proof of a shared customer, and unusual
or profitable bets do not by themselves establish access to non-public information.
